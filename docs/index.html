StudyBuddy

An AI learning partner that quizzes you on your own lecture material. Upload your slides, explain a concept in your own words, and get grounded feedback plus a sharper follow-up question, until every key concept of the topic has actually been explained.

▶ Try the live app View source on GitHub Technical documentation

The problem

Re-reading slides feels productive and proves nothing. You recognise the material without being able to explain it, and you only discover the gap in the exam. Asking a general chatbot does not help either: it answers from the internet, not from the course, so it cannot tell you whether you have understood what your lecturer actually taught.

The approach

StudyBuddy turns the material itself into the examiner. It reads your uploaded document, derives the topics and the key concepts behind each one, and then runs a Socratic dialogue: it asks, you explain, it evaluates against the material and digs into the weakest spot. A topic counts as mastered only once every key concept has been explained by you.

Grounded, not generic. Every question and every evaluation is generated from retrieved passages of your own document, with an explicit instruction never to fall back on general knowledge. If it is not in your slides, StudyBuddy will not ask about it.

What it does

Your material is the syllabus

Questions come from retrieved passages of the uploaded document only, so you are tested on the course rather than on the internet.

Mastery is defined, not guessed

Each topic is broken into 3 to 5 key concepts. The checklist is visible, and the topic closes only when all of them are covered.

Follow-ups that target the gap

A weak answer produces a single focused follow-up on the biggest gap, not a rephrasing of the same question.

Speaks the material's language

German slides produce German topics, questions and feedback. The language is inherited from the document, never configured.

No dead ends

After two follow-ups on one question the agent stops drilling and retries the concept from a fresh angle instead of looping.

Visible progress

A progress bar and a concept checklist show exactly what you have proven and what is still open.

How it works

One upload, four prompt types, and a vector index over your document. No agent framework: the pipeline is a short fixed sequence of LLM calls, which keeps it transparent and debuggable.

Step 1Parse PDF, DOCX or TXT is converted to plain text; unparseable files are rejected up front.
Step 2Index Text is chunked, embedded with all-MiniLM-L6-v2 and stored in a FAISS index for retrieval.
Step 3Extract topics Samples from the start, middle and end of the document yield the main topics.
Step 4Derive concepts The chosen topic is turned into a checklist of key concepts you must be able to explain.
Step 5Ask and evaluate One focused question per concept; your answer is graded against retrieved context as structured JSON.
↺ The mastery loop: each evaluation returns which concepts your answer genuinely covered, and those get ticked off. Remaining concepts drive the next question. The loop exits only when the checklist is complete, which is what makes "until the topic is fully explained" a measurable condition rather than a judgement call.

A session, end to end

  1. UploadDrop in a lecture PDF. Topics appear in the sidebar within seconds.
  2. Pick a topicStudyBuddy names the key concepts it will hold you to, then asks the first question.
  3. ExplainYou answer in your own words, in the chat, at whatever length you want.
  4. Get graded and pushedCorrect, partial or incorrect, with specific feedback and a follow-up aimed at what you missed.
  5. Master the topicThe checklist fills up. When the last concept is ticked, the topic is done and you move on.

Design decisions

The choices that shaped the architecture, and the reasoning behind each.

DecisionWhy
No agent framework The pipeline is a small fixed sequence of LLM calls plus one vector index. Using the OpenAI client and FAISS directly keeps the code transparent, debuggable and dependency-light.
Material as ground truth Grounding everything in the uploaded document is what makes the tool useful for exam preparation. The trade-off is deliberate and documented under limitations.
Concept checklist as the mastery criterion An explicit, inspectable definition of "fully explained", shown to the student as a checklist, instead of an opaque model judgement.
Follow-up limit with retry from a new angle Prevents frustrating dead-end loops on a single question while still refusing to skip a concept that has not been mastered.
Tolerant JSON parsing Model output arrives wrapped in code fences, reasoning blocks or prose. The parser strips all of these and falls back to a neutral evaluation, so a malformed response never ends a session.
